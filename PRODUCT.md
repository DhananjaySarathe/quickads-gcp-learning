# QuickAds Cloud Learning

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Dhananjay, a frontend developer learning backend and Google Cloud from zero, wants to operate and eventually optimize the services used by QuickAds. He uses this personal learning site between sessions with his AI tutor.

## Product Purpose

Make the path from first cloud account to independent service ownership understandable and inviting. The initial goal is a practical two-day introduction, followed by 8–12 weeks of practice. It is not a promise of expertise in two days.

## Operating Context

The user explicitly chose visual maps and short interactive lessons for this redesign. The site is a public static GitHub Pages project, accessible on desktop and phone. It needs no account of its own. Progress is saved locally, with explicit export/import for other devices.

## Capabilities and Constraints

Preserve five learning phases, thirty evidence-based milestones, progress storage key and backup compatibility, lesson prompts, and external learning resources. Use plain HTML, CSS and JavaScript built by Python's standard library into docs/. Deployment is from main/docs. Use relative asset URLs under the GitHub Pages project subpath.

No actual QuickAds cloud inventory has been supplied. Examples about advertising products must be identified as learning examples, never represented as confirmed company infrastructure. There is no real GCP control plane, billing integration, hosted AI tutor, or cross-device sync in this static site.

## Brand Commitments

Light backgrounds, readable type, and strong contrast are explicit requirements. The user rejected dark themes and a visually sparse checklist. He authorized a full aesthetic replacement, then clarified that visuals must teach through GIFs, animations and interactive knowledge rather than decorative generated images. Do not ship the earlier decorative cloud illustration.

## Evidence on Hand

The current roadmap contains 30 milestones and official Google Cloud reference links. Existing account, free-trial and spending guidance is retained and should be reverified when altered. No company architecture diagram, brand assets, or service inventory is available.

## Product Principles

- Show an idea before asking the learner to memorize it.
- Teach one manageable step and require evidence of understanding.
- Explain new terms plainly without assuming cloud knowledge.
- Keep learning examples and confirmed company facts distinct.
- Preserve progress and work well on the user's narrow in-app browser as well as full desktop.

## Accessibility & Inclusion

The user explicitly prioritizes readability. Use semantic controls, clear keyboard focus, sufficient text contrast, and reduced-motion support. Do not put essential lesson text inside raster artwork.
